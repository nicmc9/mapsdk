# Используемые крейты

Каждая сторонняя зависимость: что делает, аналог в C++ и почему выбрана.
**[Rust]** «Крейт» — единица компиляции и пакет одновременно (примерно библиотека + её CMake-таргет).
Скачиваются автоматически с crates.io при сборке, версии фиксируются в `Cargo.lock`.

## Платформа

| Крейт | Что делает | Аналог в C++ | Почему |
|-------|-----------|--------------|--------|
| `winit` 0.30 | Окна, цикл событий ОС, ввод, жизненный цикл на всех наших платформах | SDL2 (только окно и события), GLFW | Стандарт де-факто в Rust; на нём работают `wgpu`, Bevy. Ветка 0.31 пока в beta |
| `android-activity` (через `winit`) | Связь с Activity на Android: загрузка `.so`, вызов `android_main`, события жизненного цикла | `android_native_app_glue` из NDK | Подключается фичей `android-native-activity` у `winit` |

| `raw-window-handle` 0.6 | Общий интерфейс «дай native-хэндл окна» (HWND, NSView, ANativeWindow, canvas) | `void*` + enum типа окна | Через него `wgpu` создаёт surface, не зная про `winit` |
| `web-time` 1.1 | `Instant`/`Duration`, работающие в браузере | — | `std::time::Instant` в wasm паникует. На native это просто `std::time` |

## Ядро

| Крейт | Что делает | Аналог в C++ | Почему |
|-------|-----------|--------------|--------|
| `bevy_ecs` 0.20 | ECS: сущности, компоненты, ресурсы, системы, планировщик с автоматическим распараллеливанием, сообщения | EnTT + taskflow | Решение D2. Используется без остального Bevy; скрыт за `engine::ecs`. Фича `multi_threaded` — только не на wasm |

| `triple_buffer` 9 | Lock-free тройной буфер на атомиках | ручная реализация на `std::atomic` | Проверенная реализация схемы из архитектуры (раздел 4.1), без зависимостей |
| `glam` 0.34 | Векторы, матрицы, кватернионы с SIMD | GLM | Самый быстрый и популярный в Rust-геймдеве; на нём Bevy. Скрыт за псевдонимами `engine::math` |

## Задачи, сеть, ресурсы

| Крейт | Что делает | Аналог в C++ | Почему |
|-------|-----------|--------------|--------|
| `bevy_tasks` 0.20 | Пулы потоков для async-задач; на Web — `spawn_local` в цикле браузера | thread pool + `std::future` | Уже был в зависимостях через `bevy_ecs`; одинаковый API на всех платформах. Скрыт за `engine_core::tasks` |
| `futures-util` | Комбинаторы future: `Shared` (один результат — много ожидающих), `join` | `std::shared_future` | Дедупликация загрузок |
| `ureq` 3 | Синхронный HTTP-клиент, TLS через `rustls` | libcurl (easy API) | Без runtime `tokio`, проще `reqwest`. Блокирующий вызов в потоке пула IO. `rustls` тянет `ring` с C-кодом — Android собирается через `cargo ndk` |
| `wasm-bindgen-futures`, `web-sys` | Промисы JS как Rust-future; `fetch`, `AbortSignal` | — | Сеть на Web |
| `criterion` 0.8 | Микробенчмарки со статистикой и сравнением с прошлым запуском | Google Benchmark | T-02. Без графиков и rayon |
| `notify` 8 | Уведомления ОС об изменении файлов (FSEvents, inotify) | efsw / Qt `QFileSystemWatcher` | Горячая перезагрузка ресурсов, только desktop |
| `image` 0.25 | Декодирование PNG и JPEG | stb_image | Чистый Rust, работает на wasm. Включены только png и jpeg |
| `gltf` 1.4 | Разбор glTF/glb и чтение вершинных данных | cgltf / tinygltf | Буферы и внешние текстуры читаем сами через VFS — тот же кеш и сеть |

## Рендер

| Крейт | Что делает | Аналог в C++ | Почему |
|-------|-----------|--------------|--------|
| `bytemuck` | Безопасный взгляд на структуру `#[repr(C)]` как на байты (для GPU-буферов) | `memcpy` + `static_assert` на POD | Проверяет при компиляции, что в структуре нет указателей и неинициализированных байтов выравнивания |
| `egui` 0.37, `egui-wgpu` | Интерфейс «немедленного режима» и его отрисовка через wgpu | Dear ImGui | Отладочный UI. `egui-wgpu` собран под тот же wgpu 30; фичи по умолчанию (WebGL) отключены. `egui-winit` не используется — ввод переводим из своих событий |
| `wgpu` 30 | Графический API поверх Vulkan, Metal, GLES и WebGPU в браузере | Dawn / bgfx / Diligent Engine | Решение из README. Включены бэкенды Vulkan, Metal, GLES (Android) и WebGPU; DX12 и WebGL2 отключены |

## Логи и профилирование

| Крейт | Что делает | Аналог в C++ | Почему |
|-------|-----------|--------------|--------|
| `tracing` | Фасад логов и зон: события (`info!`) и спаны — интервалы времени со своими полями | spdlog + макросы зон Tracy в одном | Стандарт в Rust. Спан — это сразу и контекст для логов, и зона профайлера |
| `tracing-subscriber` | Сборка обработчиков из слоёв: форматирование, фильтр, перезагрузка фильтра на лету | sink'и spdlog | Включает мост `log` → `tracing`: логи `wgpu`, `winit` приходят сюда же |
| `tracing-logcat` | Вывод в logcat Android | `__android_log_write` | Android |
| `tracing-oslog` | Вывод в `os_log` (Console.app, Xcode) | `os_log` | iOS-устройство. В симуляторе — stderr, чтобы видеть логи в терминале |
| `tracing-web` | Вывод в консоль браузера | — | Web |
| `tracing-tracy`, `tracy-client` | Отправка спанов и кадров в Tracy | Tracy client (`ZoneScoped`, `FrameMark`) | Только с фичей `profiling`. Собирает C++-код Tracy при сборке |
| `log` | Старый фасад логов | — | Нужен только для моста: на нём пишут `wgpu` и `winit` |
| `console_error_panic_hook` | Печать паники в консоль браузера с сообщением и местом | — | Без него на Web паника выглядит как `unreachable executed` |

## Ошибки

| Крейт | Что делает | Аналог в C++ | Почему |
|-------|-----------|--------------|--------|
| `thiserror` | `#[derive(Error)]`: генерирует `Display`, `std::error::Error` и конвертацию через `#[from]` для enum ошибок | ручной класс-наследник `std::exception` | Убирает шаблонный код, не попадает в публичный API |

## Web

| Крейт / инструмент | Что делает | Аналог в C++ | Почему |
|--------------------|-----------|--------------|--------|
| `wasm-bindgen` | Связь Rust ↔ JavaScript: экспорт функций, вызов JS API | Emscripten `EMSCRIPTEN_BINDINGS` / `embind` | Стандарт для `wasm32-unknown-unknown`, на нём работают `winit` и `wgpu` |
| `wasm-bindgen-cli` (инструмент) | Постобработка `.wasm`: генерирует JS-обвязку | `emcc` на этапе линковки | **Версия обязана совпадать с крейтом `wasm-bindgen` в `Cargo.lock`**, поэтому крейт закреплён через `=` |
